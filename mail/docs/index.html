Akaros Mail API

https://api.mail.akaros.si
Markdown 源文件返回 Webmail
认证邮件转发MCP限制

认证与权限

除健康检查外，REST 与 MCP 均使用 Bearer 密钥：

Authorization: Bearer <API_KEY>
  • 管理员：全部邮件、转发规则和 catch-all。
  • 子账户：仅本人地址的邮件、附件、发件和转发规则；不能管理 catch-all 或其他地址。
  • 子账户不返回全局目标地址清单。数据库只保存子账户密钥的 SHA-256 哈希。

GET /api/me返回当前角色、账户和权限：

{
  "role": "account",
  "account": "shirobana@akaros.si",
  "manage_all_accounts": false,
  "manage_catch_all": false
}

管理员 role 为 admin，account 为 null。

响应与错误

成功响应为 JSON，附件接口返回二进制。错误格式：

{"error": "错误说明", "details": {}}

常见状态码：400 参数错误；401 密钥无效；403 权限不足；404 不存在或无权访问；409 冲突；502 SMTP/上游错误；503 未配置。

邮件 API

健康检查

GET /api/health无需认证。

发件

POST /api/send

{
  "from": "no-reply@akaros.si",
  "from_name": "Akaros Mail",
  "to": ["recipient@example.com"],
  "cc": [],
  "bcc": [],
  "subject": "测试",
  "text": "纯文本正文",
  "html": "<p>可选 HTML 正文</p>",
  "in_reply_to": "<optional-id@example.com>",
  "references": "<optional-id@example.com>",
  "attachments": [
    {"name":"hello.txt", "type":"text/plain", "data":"aGVsbG8="}
  ]
}
  • 管理员省略 from 时使用 no-reply@akaros.si；子账户只能使用自身地址。
  • to、cc、bcc 至少一项，总计最多 50 个地址。
  • 附件最多 10 个，总计 10 MiB；data 为不带 data URL 前缀的 base64。
  • 成功返回 201，包含 message 和 smtp_response；失败保存 failed 记录。

邮件列表

GET /api/messages?folder=inbox&limit=50

参数说明
folderinbox（默认）、sent、failed、outbox、trash、all
direction可选，in 或 out
q可选，按主题、发件人或摘要搜索
limit1–100，默认 50

子账户仅返回 mailbox 等于自身地址的记录。

详情与管理

方法与路径用途
GET /api/messages/:id完整正文、地址、状态、Message-ID、附件元数据
PATCH /api/messages/:id{"is_read":true} 或 {"folder":"inbox|trash"}
DELETE /api/messages/:id移入垃圾箱
DELETE /api/messages/:id?permanent=1永久删除邮件、正文及附件对象
GET /api/attachments/:id带 Bearer 认证下载原始附件

发件记录从垃圾箱恢复时回到其发件文件夹。子账户访问其他邮件或附件返回 404。

Email Routing API

转发规则采用双份留存：邮件先保存到 D1，再由 Worker 调用 message.forward()。Cloudflare 控制台显示 Worker 是预期行为；转发失败不会删除 Webmail 副本。

方法与路径用途
GET /api/routing返回 settings、rules、catch_all、destinations、access
POST /api/routing/rules新增本域地址转发规则
PUT /api/routing/rules/:id修改目标、名称或启停状态
DELETE /api/routing/rules/:id删除普通规则及 D1 映射
PUT /api/routing/catch-all管理员配置 worker、drop 或 forward
POST /api/routing/destinations添加目标地址并触发 Cloudflare 验证邮件

新增规则

{
  "address": "user@akaros.si",
  "destination": "verified@example.com",
  "name": "可选名称",
  "enabled": true
}

目标地址必须已验证且不能与收件地址相同。子账户只能管理自身地址。

catch-all（仅管理员）

{"enabled":true,"action":"worker"}

forward 动作需要 destination，也支持先存 D1 再转发。子账户调用返回 403；读取时 catch_all 为 null、destinations 为 []。

添加目标地址

{"email":"destination@example.com"}

Webmail 不展示已有验证地址或自动补全，目标地址需要手动输入。

MCP

POST /mcp使用同一个 Bearer API Key，采用无状态 Streamable HTTP。

支持 initialize、版本协商、ping、tools/list、tools/call 和通知；协议版本为 2024-11-05、2025-03-26、2025-06-18、2025-11-25、2026-07-28。

{
  "mcpServers": {
    "akaros-mail": {
      "type": "http",
      "url": "https://api.mail.akaros.si/mcp",
      "headers": {"Authorization":"Bearer <API_KEY>"}
    }
  }
}
工具用途
send_email发件，参数与 REST 发件相同
list_emailsfolder、direction、q、limit
get_email按 id 读取完整邮件
get_attachment按 id 返回附件元数据和 data_base64

MCP 与 REST 使用相同账户权限。

限制与存储

  • 单封接收邮件默认最大 20 MiB，最多 15 个附件。
  • 发件正文单种格式最大 2 MB；最多 50 个收件地址。
  • 发件附件最多 10 个，总计 10 MiB。
  • 正文与附件在 D1 中分块存储。
  • API 不返回 Cloudflare、Brevo 或其他账户密钥。
